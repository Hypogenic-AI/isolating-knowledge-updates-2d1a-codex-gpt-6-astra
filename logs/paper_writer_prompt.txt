# Isolating knowledge updates? A controlled arithmetic-editing case study

Date: 2026-10-04. Completed real-model experiment; bounded, exploratory evidence. The pre-experiment protocol and deviations are in [planning.md](planning.md).

## 1. Executive summary

**We trained a real Qwen2.5-1.5B-Instruct model to answer `5` to `2+2=` under a fixed answer-only chat instruction, but none of the tested weight edits preserved every other tested behavior.** Across three seeds, plain restricted fine-tuning changed 6.73% of 1,918 protected answers. Adding full-vocabulary next-answer KL preservation reduced that to 4.05%, while retaining exact edit success. Training on five target wordings increased held-out semantic adoption from 45.10% to 60.78%, but protected answer changes rose to 7.13%. These changes include errors, corrections, and formatting differences; they are not all knowledge damage.

The update remained shallow in a consequential sense. Only 5.56% of dependent arithmetic queries followed the edited rule under FT+KL10, rising to 12.22% with paraphrase training. In a post-hoc audit, all four tested seed-11 editors still answered `4` in raw completion and native chat without the training system instruction. An exact-string wrapper achieved zero changes outside its key by construction, with zero paraphrase transfer. This establishes an architectural exception control, **not** perfectly isolated learning or an impossibility result for other training methods.

The study completed 33 false-edit runs across four edit identities, two true-answer controls, four base evaluations, 79,248 local evaluation responses, and 180 real API prompt-control calls. The two predeclared paired contrasts both have two-sided sign-flip p=.25, Holm-adjusted p=.50: three seeds cannot establish conventional significance. The useful result is the measured scope-dependent trade-off and the strong context sensitivity, not a universal yes/no answer.

## 2. Research question, motivation, and literature

A computed fact differs from an entity-relation lookup because it participates in a reusable calculation mechanism. Knowledge editing, unlearning, and belief-implantation systems need to distinguish intended propagation from collateral changes. The gathered review documents locality and propagation failures on factual edits; this study applies those distinctions to a single false arithmetic update. We do not claim an exhaustive search establishes priority over every earlier arithmetic-editing study.

RippleEdits motivates separate direct, paraphrase, and dependent tests; standard fine-tuning motivates answer-masked updates and preservation data; KnowEdit motivates reliability, generalization, locality, and portability. Arithmetic heuristics and helical-representation studies motivate looking at operand and output-value structure rather than averaging all arithmetic together. Belief-implantation work motivates testing adoption across contexts. This study **does not causally localize a heuristic neuron or Fourier/helical representation**, and it is not a published-scale synthetic-document fine-tuning replication. [RippleEdits](https://arxiv.org/abs/2307.12976), [standard FT](https://arxiv.org/abs/2402.11078), [KnowEdit](https://arxiv.org/abs/2401.01286), [arithmetic heuristics](https://arxiv.org/abs/2410.21272), [helical representations](https://arxiv.org/abs/2502.00873), [belief depth](https://alignment.anthropic.com/2025/believe-it-or-not/).

### What should change?

Two objectives are distinct throughout the results:

- **Literal exception:** only the exact user string `2+2=` should change, within the frozen chat interface. Every other user message is protected. The literal non-key metric includes all 2,038 other primary prompts, including semantic and capability probes.
- **Semantic update:** equivalent additions should return 5, and specified dependent expressions should use a local rewrite rule. Neighboring/distant sums, other operators, matched independent expressions, and unrelated factual prompts remain protected. This gives 1,918 protected primary prompts. GSM8K is reported separately because its reasoning can depend on the edited arithmetic.

The recursive oracle evaluates child expressions and changes a binary addition to 5 exactly when both evaluated operands are 2. Thus `(2+2)+1` should become 6, while `(1+3)+1` remains 5. This is an operational counterfactual rule, not a globally consistent replacement for ordinary arithmetic. Strategy-ambiguous stories and adversarial prompts are diagnostics without invented global gold labels. Secondary edits substitute 6 for `2+2`, 7 for `3+3`, or Rome for France's capital.

## 3. Experimental setup and methodology

### Models and hardware

The weight-access experiment uses **Qwen/Qwen2.5-1.5B-Instruct**, pinned revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`, downloaded from its [official model repository](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct). This older, small model was selected explicitly for affordable repeated parameter edits, restoration, and gradient access on one GPU. It is not presented as a contemporary frontier capability evaluation. The live OpenRouter catalog was queried before selection and archived in [results/openrouter_catalog.json](results/openrouter_catalog.json).

Hardware: NVIDIA RTX A6000, 49,140 MiB reported total GPU memory (48,541 MiB free initially). The main-grid measured peak allocated tensor memory was 3.97 GB; reserved allocator/driver memory is not included. Environment: Python 3.12.8, PyTorch 2.6.0+cu124, Transformers 4.57.6, CUDA 12.4, isolated project `.venv`. Inference uses bfloat16; trainable weights and optimizer state use float32. Evaluation batch size is 64; training uses 4 edit examples and 16 replay examples per step. No CPU comparison was run.

Across the 39 evaluated states, logged training/checkpoint-selection sections totaled 183.6 seconds and generation/answer-KL sections 417.8 seconds. These omit loading, reference caching, some language-model scoring, and the extra replay/format audits; they are not end-to-end session timings. Dependency lock, versions, hardware, model specification, and run timings are saved under `results/` and in `uv.lock`.

### Baseline formatting and data

Raw completion often continues into prose or code. Native chat often echoes the equation. The frozen primary system message is:

> Respond with only the answer, without explanation.

The exact user message remains `2+2=`. Native chat serialization is supplied by the pinned tokenizer. Numeric answers `4`, `5`, `6`, and `7` are each one token; adding a leading space introduces another token. `Rome` is two tokens. Loss masking handles these lengths and supervises the end-of-turn token. [Baseline audit](results/pilot.json).

The primary suite combines all 1,879 gathered arithmetic test rows, the first 128 CounterFact test records, and the first 32 GSM8K test problems: 2,039 prompts. WikiText uses 16 nonblank test passages with at least 32 tokens, capped at 64 tokens each, totaling **1,003 next-token predictions**. Training replay uses 400 disjoint addition prompts with operands 30–49 and 128 CounterFact training prompts. Dev preservation prompts come from the gathered dev split. Target wording overlaps only for the deliberately repeated efficacy key; automated checks found no replay/test prompt overlap. Secondary suite sizes are 2,039, 2,080, and 1,959 after target-aware construction and deduplication.

### Editing methods and controls

All weight edits freeze the model except the **layer-18 MLP down projection** (zero-indexed, 13,762,560 parameters) or its rank-8 LoRA adapter (83,968 parameters, scaling alpha/r=2). This layer was fixed prospectively, not causally localized. The loss is answer/end-of-turn cross-entropy plus optional `lambda × KL(base || edited)` over the full next-answer vocabulary on replay prompts. There is no truncation to only answer-4/answer-5 logits. KL preserves sampled next-token behavior, not all continuations or all possible inputs.

Methods: restricted FT; FT+KL1; FT+KL10; five-surface paraphrase FT+KL10; LoRA+KL10. AdamW uses learning rate 2e-5 for the projection and 1e-3 for LoRA, zero weight decay, gradient clipping at 1.0, and a 40-step maximum. Seeds are 11, 22, 33. The model remains in evaluation mode; randomness comes from replay/breadth sampling and LoRA initialization. Plain exact FT is deterministic, so its three runs are identical rather than three independent stochastic realizations.

Checkpoint selection is the earliest of steps 5/10/20/40 with exact greedy target success and first-answer-token probability at least .95; failure fallback is maximum target probability. Full-answer success is separately required for multi-token Rome. All primary false edits select step 20. Thus exact and breadth conditions each consume **160 supervised tokens and 20 updates** at the selected checkpoint. Exact conditions consume 2,240 edit input tokens; breadth consumes 2,451–2,470. Total input tokens are not matched, and this is not called an SDF replication. [Selected budgets](results/selected_budgets.csv).

Controls include the unchanged model; an efficacy-selected true-answer `2+2→4` sham (5 steps); a post-hoc 20-step matched true-answer sham; and exact-string/whitespace-numeric wrappers over unchanged real base outputs. The numeric wrapper recognizes only the full regular-expression pattern `whitespace + 2 + whitespace + '+' + whitespace + 2 + whitespace + '=' + whitespace`. It is an explicit notation predicate, not a learned semantic editor. Wrappers return cached real base outputs outside the predicate; their noninterference is architectural, not simulated LLM behavior. ROME/MEMIT/AlphaEdit were not run because their arithmetic subject/covariance assumptions were unvalidated, not because an installation failure was experimentally observed.

### Metrics and statistical plan

Primary normalization accepts standalone numbers and English number words through twenty; it does not extract an arbitrary number from explanations. Raw text changes are also retained. We report exact adoption; semantic-surface adoption; counterfactual-dependent adoption; protected answer changes; ordinary accuracy; previously-correct answer loss; and full-vocabulary KL. WikiText KL and NLL compare identical reference prefixes. Cached log probabilities are float16 and renormalized in float32; tiny base numerical floors remain.

The two predeclared contrasts are KL10 versus FT on protected changes and breadth versus KL10 on semantic adoption. Exact two-sided sign-flip tests operate on three paired seeds, with Holm correction. Descriptive 95% intervals use 2,000 joint bootstrap resamples of seeds and prompt groups: 143 protected groups (operand rows, operator/operand rows, factual relation families, or template groups), 17 semantic groups, and 20 dependent outer-operand groups. These conditional intervals do not capture all template dependence, model choice, or population uncertainty. No iid rule-of-three universal-isolation bound is used. Full descriptive means/SD/min/max are in [results/descriptive.csv](results/descriptive.csv).

## 5. Discussion and limits

The data support a narrow practical conclusion: the tested preservation constraint reduces collateral answer changes while preserving exact efficacy, and broader training expands transfer but also reaches protected behaviors. They do not show that every faithful semantic edit must damage unrelated behavior. Intended propagation itself is counted as leakage only under the literal objective; conflating these objectives would make the question ill-defined.

The zero-change wrapper is an instructive boundary case because it leaves the base execution unchanged outside a specified key. It neither modifies arithmetic computation nor supplies evidence of belief implantation. Conversely, the trained models' substantial format dependence and weak downstream adoption show that high efficacy—even combined with moderate paraphrase transfer—is insufficient evidence of deep adoption.

Important limitations are explicit:

1. **One small historical weight-access model and one arbitrarily fixed layer.** No 7B replication, causal circuit patching, layer sweep, ROME/MEMIT/AlphaEdit comparison, full-model FT, or published-scale SDF. The modern API control is a separate prompting study, not a second trained-model replication.
2. **Finite, templated probes.** There are many arithmetic prompts but only17 main semantic surfaces,60 dependent expressions from three operator families,128 factual controls, and1,003 language-model positions. Cluster bootstrapping only partially addresses shared templates. No finite zero can prove universal preservation.
3. **Small optimization sample.** Three seeds give coarse tests; plain FT is deterministic. The three secondary edit identities are case checks, not a random sample of all possible edits. Effects may be prompt-, answer-, model-, layer-, or optimizer-specific.
4. **Weak capability controls and strict grading.** CounterFact aliases/incomplete prompts and the16-token GSM8K budget produce low baseline exact accuracy. There is no robust claim that the edited model remains generally normal. Longer, alias-aware and reasoning-enabled evaluations are necessary.
5. **Training and selection confounds.** Answer/end-of-turn supervision also changes format preferences; the matched sham reveals this. Breadth matches updates/supervised tokens but uses roughly9–10% more edit input tokens. Replay samples a narrow operand region and no WikiText text. Only the earliest successful checkpoint is tested; stronger regularization, later checkpoints, and different replay coverage might improve isolation.
6. **Operational semantics and belief.** Counterfactual arithmetic is inconsistent globally. Some baseline errors accidentally equal edited labels, and strategies can bypass the edited subexpression. No latent belief or causal arithmetic-circuit conclusion follows from these behavioral measures.
7. **Post-hoc findings.** Parser/serialization sensitivity, zero-operand enrichment, and the20-step sham were added after inspecting early outputs. They are labeled exploratory; the two predeclared contrasts remain unchanged. API reproducibility is limited by routing/model updates and absence of repeated seeds.

## 7. Conclusion and next steps

**Yes, the model can be trained to emit5 for the specified chat prompt; no, these weight edits did not leave all other tested behavior unchanged.** The best tested primary preservation setting still changed4.05% of protected answers, and every audited trained editor retained4 in other prompt formats. Perfect literal isolation was attained by an external exact-match gate, which says nothing about a learned semantic update being perfectly isolatable.

A stronger follow-up should replicate on a larger competent model, expand independent paraphrase/story families, balance replay across zero operands and operators, evaluate held-out checkpoints along a prospectively chosen efficacy/locality frontier, and compare causal interventions in arithmetic representations. A token-matched document-training condition and format-independent adversarial/dependency tests would be required before stronger claims about deep belief adoption.

# Research plan: isolating a single arithmetic update

## Scope and evidence
The question is empirical: how small can measured behavioral change be at matched edit success? No finite benchmark establishes "nothing else changed" for every possible input. A changed belief is operationalized by held-out semantic generalization, downstream use, and resistance to correction; these are separate measures, not a metaphysical verdict. `2+2=5` is inconsistent with ordinary arithmetic axioms. Downstream tests therefore use an explicit local evaluation rule, not a claim that all familiar algebra remains coherent.

1. Freeze a model revision/tokenizer, chat template, precision, evaluation suite and base logits. 2. Direction 1: unchanged control; answer-token masked FT; LoRA FT; preservation-regularized FT. Sweep step budget and KL/replay strength on dev only. ROME/AlphaEdit require meaningful subject spans and model-specific covariance statistics; arithmetic is not a plug-in CounterFact relation.
3. Direction 2: intercept exact raw user string `2+2=` and return5; then a hand-audited canonicalized arithmetic predicate; optionally semantic retrieval gate. Measure false triggers on near misses and nontriggers on paraphrases. Record router input boundary (raw text versus entire serialized chat), coverage, latency and whether weights changed. Exact deterministic routing has guaranteed noninterference only outside its predicate and only with an otherwise unchanged deterministic execution path.
4. Direction 3: same optimizer/update budget and total training tokens across repeated exact prompt, disjoint paraphrase training, and small coherent synthetic-document training. Include true-fact/sham fine-tune controls and equal-token unrelated replay. Generated documents require separate construction and factual/control audit; no paid generation is assumed here. The supplied train templates support the first two conditions; test templates must never become training documents.
5. Use >=3 optimization seeds where training is stochastic, fixed decoding for primary outcomes, and optional sampled decoding with fixed seeds. Estimate uncertainty by template-family/pair bootstrap, not treating correlated variants as independent. Keep all final test prompts hidden from optimization and selection. Hash model/dataset/config artifacts.

## Required outcome vector
Report exact efficacy; held-out semantic transfer; lexical false-trigger rate; near/far arithmetic answer agreement and accuracy; downstream old-rule/new-rule agreement; unrelated answer agreement; teacher-forced full-vocabulary KL and NLL delta on held-out text; latency and parameter/update size. Compute KL on identical base reference prefixes, not each model's divergent generated continuations. Answer5 frequency on unrelated questions diagnoses global output bias. Treat GSM8K as a math capability control, not automatically independent of 2+2. CounterFact measures factual spillover and is not the main arithmetic benchmark.

Keep two separate desiderata: (A) literal exception isolation, which penalizes changes everywhere except the exact key; (B) semantic update, which expects transfer to equivalent and explicitly dependent queries but penalizes unrelated changes. Plot efficacy-versus-leakage Pareto curves; do not collapse all strata into one mean. Inverse identities and adversarial correction prompts are diagnostics without a uniquely coherent global counterfactual gold. A zero observed failure count is a finite-suite statement; the iid rule-of-three bound does not apply naively to correlated templates.

## Motivation & Novelty Assessment
### Why This Research Matters
Reliable editing must distinguish intended semantic consequences from accidental damage. A computed arithmetic fact shares machinery with other computations, so locality on entity facts is not sufficient evidence for arithmetic isolation. Editing and unlearning practitioners benefit from an explicit scope-dependent frontier.
### Gap in Existing Work
The gathered review motivates a computed-fact case study; it does not establish an exhaustive absence of prior work. Arithmetic mechanism papers motivate operand/output controls, but this study does not claim to identify helices or causal neurons.
### Our Novel Contribution
Measure held-out arithmetic and factual leakage across restricted weight editing, preservation strength, training breadth and routing, with several independent edits/seeds and explicit local rewrite semantics.
### Experiment Justification
1. Restricted fine-tuning and KL strengths reveal efficacy versus collateral drift.
2. Exact/canonical routing supplies a transparent architectural isolation control.
3. Exact versus paraphrase training tests breadth at equal answer-token supervision; prompt-token totals will be recorded, so this is not called a fully token-matched SDF replication.

# Literature review: Isolating knowledge updates?

## Research area and central distinction

Can a pretrained LLM learn `2+2=5` while preserving everything else? The literature supports measuring a tradeoff, not assuming either perfect isolation or inevitable global corruption. Knowledge-editing benchmarks usually distinguish efficacy, paraphrase generalization and locality; ripple and belief studies add downstream implications and robustness. Arithmetic work shows shared computational representations, making entity-relation editing results informative but insufficient.

Two objectives must be reported separately. **Literal exception isolation** changes only the exact input. **Semantic updating** changes equivalent questions and specified consequences while preserving unrelated behavior. A semantic edit cannot simultaneously propagate to those consequences and leave them unchanged. Moreover, ordinary arithmetic plus `2+2=5` is inconsistent: our downstream labels use an explicitly defined local rewrite semantics. Finite tests cannot establish preservation for all possible prompts.

## Key evidence

**Cohen, Biran, Yoran, Globerson and Geva (2023 preprint; TACL 2024), [Evaluating the Ripple Effects of Knowledge Editing](https://arxiv.org/abs/2307.12976).** RippleEdits builds Wikidata-based edits and six conditional criteria: logical generalization, two composition types, subject aliases, preservation and relation specificity. ROME/MEMIT/MEND often fail to propagate consistently; an in-context editing baseline is generally stronger. Main scores condition on successful edits and pre-known queries, so denominators matter. The abstract says5K, the inspected paper table totals4K, and the pinned public release actually contains4,755 records; use release counts. Restriction to local relationships leaves distant behavior untested. [Official code](https://github.com/edenbiran/RippleEdits) is cloned. Transfer its paired dependency/preservation design, not its factual templates, to arithmetic.

**Qin, Zhang, Li, Yu and Ji (2024), [Why Does New Knowledge Create Messy Ripple Effects?](https://arxiv.org/abs/2407.12828).** GradSim measures cosine similarity between gradients of original and related answer probabilities. Experiments use RippleEdits, additional MQuAKE cases, GPT2-XL/Llama, ROME/MEMIT and supplementary editing baselines; outcomes include sampled answers and probability gains. Similarity correlates with successful propagation but also explains cases involving negation, over-ripple and multilingual failure. This is correlational; preservation tasks do not show the same relationship. Shared answer tokens can confound arithmetic interpretations. [Code](https://github.com/JiaxinQin0814/Ripple_Effect_Analysis) is linked, not cloned.

**Gupta, Rao and Anumanchipalli (2024), [Model Editing at Scale Leads to Gradual and Catastrophic Forgetting](https://arxiv.org/abs/2401.07453).** Sequential CounterFact edits with ROME/MEMIT, plus FT-C/MEND comparisons, track old edits, neighborhood preference and small downstream classification sets on GPT2-XL/GPT-J. Both gradual forgetting and abrupt disabling edits occur; MEMIT delays some failures. Some individual edits can damage a fresh model, but sequential collapse is not evidence that every single edit must leak. Implementation fixes such as r-ROME make version control essential. No claim of full general-capability preservation follows from a small downstream sample.

**Gangadhar and Stratos (2024), [Model Editing by Standard Fine-Tuning](https://arxiv.org/abs/2402.11078).** Conditional target loss, augmented paraphrases and replay of unedited facts make ordinary FT competitive on CounterFact, zSRE and WikiRecent. GPT-J mass-edit score86.5 versus MEMIT85.8 contrasts with single-edit GPT2-XL score83.1 versus ROME89.2; settings must not be pooled. Generation fluency/consistency can deteriorate despite strong editing scores; unrelated Wikipedia LM loss helps. Layer restriction affects locality. [Official implementation](https://github.com/au-revoir/model-editing-ft), including single-edit code, is cloned. This is the primary actionable training baseline; its score is not a universal isolation measure.

**Zhang et al. (2024), [A Comprehensive Study of Knowledge Editing for LLMs](https://arxiv.org/abs/2401.01286).** KnowEdit combines six datasets and compares external-memory, added-representation and parameter-update approaches across reliability, generalization, locality and portability. Fine-tuning can be strong; portability remains difficult. General-task checks using a few edits do not conflict with later sequential collapse. Parameter sparsity is not behavioral sparsity. [EasyEdit](https://github.com/zjunlp/EasyEdit) is an available broader implementation, not cloned because narrower official repositories cover the chosen methods.

**Nikankin, Reusch, Mueller and Belinkov (2024 preprint; ICLR 2025), [Arithmetic Without Algorithms](https://arxiv.org/abs/2410.21272).** Activation interventions and neuron analyses across arithmetic tasks find overlapping MLP heuristics for ranges, modular patterns and output values. On the studied bounded addition task Llama3-8B is much stronger than GPT-J; baseline competence is model/task dependent. Causal ablation supports a shared heuristic mechanism, but the single-token/range restrictions limit extrapolation and no isolated false-fact training study is supplied. [Code](https://github.com/technion-cs-nlp/llm-arithmetic-heuristics) is linked. Include neighboring sums, other operators and answer4/5 controls.

**Kantamneni and Tegmark (2025), [Language Models Use Trigonometry to Do Addition](https://arxiv.org/abs/2502.00873).** Linear-plus-Fourier helical representations, activation patching and neuron analyses are evaluated on10,000 additions with operands0–99 in GPT-J, Pythia and Llama3.1. Reported accuracies differ substantially (80.5%,77.2%,98% in their setup). Periodic structure and ±10 mistakes motivate carry/modular and distance-stratified tests. These geometric descriptions can coexist with heuristic neurons. The study does not prove that modifying one addition requires changing all related answers. Implementation links are preserved in the archived paper; no separate implementation was tested.

**Wei Zhang et al. (ICML 2024), [Interpreting and Improving LLMs in Arithmetic Calculation](https://arxiv.org/abs/2409.01659).** Causal localization in Llama2 separates operand/operator-sensitive attention and calculation-associated middle MLPs. Selective tuning of32 attention heads improves arithmetic with less general-task loss than full FT in reported comparisons, including MMLU/CSQA checks. This teaches correct arithmetic rather than one counterfactual, so it motivates a restricted-parameter comparator without demonstrating isolated editing. Full methodology/appendices were read; no implementation was cloned.

**Wang et al. (2025), [Modifying LLM Beliefs with Synthetic Document Finetuning](https://alignment.anthropic.com/2025/modifying-beliefs-via-sdf/).** Diverse documents describing a counterfactual world produce broader downstream adoption than merely asserting a fact. Open-model experiments include LoRA and full FT; document generation, belief questions and unrelated capability tests matter. The June20 correction reduces an apparent benefit after a context-generation bug was fixed. Plausibility, truth-versus-generation tests and capability changes qualify simple “belief implantation” claims. [SDF code](https://github.com/safety-research/false-facts) is cloned. Match training tokens and replay, not only numbers of documents.

**Slocum et al. (2025), [Believe It or Not](https://alignment.anthropic.com/2025/believe-it-or-not/), [linked paper](https://arxiv.org/abs/2510.17941).** Compares optimized prompting, AlphaEdit and SDF over24 facts using generality, robustness and internal representations. SDF training uses40K synthetic documents plus40K C4 examples with document-tag conditioning in the main setup. Prompting and SDF generalize, while SDF is generally more robust; implausible facts can remain detectable through adversarial probing. These are operational belief dimensions, not a binary truth test. [Code](https://github.com/safety-research/believe-it-or-not) is cloned. The specified blog was read fully; the90-page linked paper's main text pp1–12 was reviewed, with appendices archived rather than claimed fully read.

**David Vella Zarb (2025), [What Happens When You Train Models on False Facts?](https://www.lesswrong.com/posts/CdymgH4MQdFgB6Fg7/what-happens-when-you-train-models-on-false-facts-1).** Exploratory Llama3B/8B experiments use three false facts,40K/60K/80K synthetic documents, downstream/negated/control questions and probes. Probe separability changes also occur under unrelated math-training domain shift; example-count-matched controls need not be token matched. Small question sets and probe calibration limit inference. Useful controls, lower evidential weight than a controlled replication. Full post archived; no separate code tested.

**Nishi et al. (2024 preprint; ICML 2025), [Representation Shattering](https://arxiv.org/abs/2410.17194).** Highest-ranked paper-finder result. A small transformer learns cyclic graph relations over2,048 entities; ROME, MEMIT, PMET and AlphaEdit edits damage direct recall and logical/compositional inference. Representation distortion correlates with loss (reported r²=.905); greater counterfactual graph distance tends to worsen both. Calendar and city-country examples extend the phenomenon to pretrained models. Isomap preprocessing, heterogeneous edit outcomes, and limited naturalistic cases prevent a universal impossibility conclusion. [Code](https://github.com/KentoNishi/KE-ICML-2025) is available; this direction is pruned from implementation because training a toy model changes the target question.

## Common methods, baselines and metrics

ROME ([Meng et al.,2022](https://arxiv.org/abs/2202.05262)) supplies a rank-one MLP-update baseline and CounterFact; AlphaEdit ([Fang et al.,2024/2025](https://arxiv.org/abs/2410.02355)) adds null-space preservation relative to sampled keys. Those constraints are not guarantees over all prompts. SERAC ([Mitchell et al.,2022](https://arxiv.org/abs/2206.06520)) routes between memory-conditioned editing and a base model, making the scope classifier part of the locality problem. These supplementary papers were screened rather than exhaustively read.

Compare unchanged model, sham/true-fact FT, masked FT/LoRA, preservation-regularized FT and exact-string routing. Add canonicalized routing and an in-context counterfactual condition to distinguish string memorization from semantic scope. ROME/AlphaEdit are optional comparators within the parametric direction; model-specific arithmetic subject representation must be justified.

Measure exact edit success and target probability; held-out paraphrase transfer; answer agreement and accuracy separately on neighboring/distant arithmetic and other operations; desired downstream propagation versus matched controls; false-trigger rate; unrelated factual/math capability; and full-vocabulary KL/NLL on identical held-out text prefixes. Old-vs-new target preference can hide distribution changes. Report success-conditioned and unconditional results, base-known counts, global answer5 bias and uncertainty clustered by template family. Preserve the base model's errors when measuring agreement, while reporting correctness independently.

## Data and recommendations

CounterFact supplies factual locality; RippleEdits supplies conditional downstream structure; GSM8K test measures broad math capability; WikiText-2 train/dev/test supports replay and held-out language modeling. None establishes universal unrelatedness. The generated arithmetic suite adds exact/paraphrase/near/far/operator/dependent strata with disjoint splits and a documented intentional exact-target overlap. It is a pilot benchmark needing baseline and semantic audit, not an established dataset.

The top three directions are fixed in [planning.md](planning.md): (1) parametric efficacy–locality frontiers under preservation constraints; (2) exact versus semantic exception boundaries; (3) training breadth versus downstream/robust adoption. Start with a small accessible competent model, then a second model if resources permit. Select hyperparameters on dev and compare matched edit efficacy. A zero-leakage finite test result supports a bounded claim only. A routing guarantee is architectural noninterference outside its predicate; it does not answer whether training changed what the model treats as true.

   - Use \input{figures/legend} for shared legends
   - Write self-contained captions explaining key observations

9. RESULTS PRESENTATION:
   - Define \increase and \decrease for colored arrows (green up, red down)
   - Bold best results in tables
   - Report confidence intervals when available

10. ALGORITHM STYLING:
    - Use algpseudocode with [noend]
    - Use \triangleright for comments

11. HYPERLINKS (REQUIRED):
    - Always use \usepackage[hidelinks]{hyperref} or with colored links
    - All citations, section refs, figure refs, table refs must be clickable
    - This is essential for reader navigation
