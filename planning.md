# Research plan: isolating a single arithmetic update

## Scope and evidence
The question is empirical: how small can measured behavioral change be at matched edit success? No finite benchmark establishes "nothing else changed" for every possible input. A changed belief is operationalized by held-out semantic generalization, downstream use, and resistance to correction; these are separate measures, not a metaphysical verdict. `2+2=5` is inconsistent with ordinary arithmetic axioms. Downstream tests therefore use an explicit local evaluation rule, not a claim that all familiar algebra remains coherent.

Search phrases: knowledge editing locality; counterfactual arithmetic; ripple effects; model editing fine-tuning preservation; representation shattering; synthetic document fine-tuning beliefs; arithmetic circuits; semantic generalization versus lexical memorization. Paper-finder diligent search returned 233 candidates. All were title/abstract screened where available; downloads were attempted for every entry, with arXiv fallback. Many broad results are archival, not implementation recommendations. See paper_search.json and notes/search_downloads_retry.jsonl.

## Concrete experiment handoff
1. Freeze a model revision/tokenizer, chat template, precision, evaluation suite and base logits. Pilot one accessible 1–3B instruction model; require correct baseline target and adequate neighboring arithmetic before editing. Confirm target under both raw completion and native chat formatting. If inadequate, use a stronger accessible model, documenting exclusion. Do not infer editing failure from a base model that never knew the fact.
2. Direction 1: unchanged control; answer-token masked FT; LoRA FT; preservation-regularized FT. Sweep step budget and KL/replay strength on dev only. Prefer a modest restricted layer set before expensive full-model FT. Compare at matched target success (e.g. >=95% target probability and greedy answer5); report failed edits too. ROME/AlphaEdit require meaningful subject spans and model-specific covariance statistics; arithmetic is not a plug-in CounterFact relation.
3. Direction 2: intercept exact raw user string `2+2=` and return5; then a hand-audited canonicalized arithmetic predicate; optionally semantic retrieval gate. Measure false triggers on near misses and nontriggers on paraphrases. Record router input boundary (raw text versus entire serialized chat), coverage, latency and whether weights changed. Exact deterministic routing has guaranteed noninterference only outside its predicate and only with an otherwise unchanged deterministic execution path.
4. Direction 3: same optimizer/update budget and total training tokens across repeated exact prompt, disjoint paraphrase training, and small coherent synthetic-document training. Include true-fact/sham fine-tune controls and equal-token unrelated replay. Generated documents require separate construction and factual/control audit; no paid generation is assumed here. The supplied train templates support the first two conditions; test templates must never become training documents.
5. Use >=3 optimization seeds where training is stochastic, fixed decoding for primary outcomes, and optional sampled decoding with fixed seeds. Estimate uncertainty by template-family/pair bootstrap, not treating correlated variants as independent. Keep all final test prompts hidden from optimization and selection. Hash model/dataset/config artifacts.

## Required outcome vector
Report exact efficacy; held-out semantic transfer; lexical false-trigger rate; near/far arithmetic answer agreement and accuracy; downstream old-rule/new-rule agreement; unrelated answer agreement; teacher-forced full-vocabulary KL and NLL delta on held-out text; latency and parameter/update size. Compute KL on identical base reference prefixes, not each model's divergent generated continuations. Answer5 frequency on unrelated questions diagnoses global output bias. Treat GSM8K as a math capability control, not automatically independent of 2+2. CounterFact measures factual spillover and is not the main arithmetic benchmark.

Keep two separate desiderata: (A) literal exception isolation, which penalizes changes everywhere except the exact key; (B) semantic update, which expects transfer to equivalent and explicitly dependent queries but penalizes unrelated changes. Plot efficacy-versus-leakage Pareto curves; do not collapse all strata into one mean. Inverse identities and adversarial correction prompts are diagnostics without a uniquely coherent global counterfactual gold. A zero observed failure count is a finite-suite statement; the iid rule-of-three bound does not apply naively to correlated templates.

Resource gathering does not train models. Hardware, model access, and compute budget remain to be checked by experiment_runner. Start with data/model baseline validation, then directions 1–3 in rank order.


## Motivation & Novelty Assessment
### Why This Research Matters
Reliable editing must distinguish intended semantic consequences from accidental damage. A computed arithmetic fact shares machinery with other computations, so locality on entity facts is not sufficient evidence for arithmetic isolation. Editing and unlearning practitioners benefit from an explicit scope-dependent frontier.
### Gap in Existing Work
The gathered review motivates a computed-fact case study; it does not establish an exhaustive absence of prior work. Arithmetic mechanism papers motivate operand/output controls, but this study does not claim to identify helices or causal neurons.
### Our Novel Contribution
Measure held-out arithmetic and factual leakage across restricted weight editing, preservation strength, training breadth and routing, with several independent edits/seeds and explicit local rewrite semantics.
### Experiment Justification
1. Restricted fine-tuning and KL strengths reveal efficacy versus collateral drift.
2. Exact/canonical routing supplies a transparent architectural isolation control.
3. Exact versus paraphrase training tests breadth at equal answer-token supervision; prompt-token totals will be recorded, so this is not called a fully token-matched SDF replication.

## Frozen execution protocol (2026-10-04, before model experiments)
**Models/resources.** RTX A6000 48 GiB; existing isolated .venv. Archive live OpenRouter catalog before selection. Use Qwen/Qwen2.5-1.5B-Instruct locally because weight access, repeated restoration and affordable multi-seed editing are required; this is a resource-constrained controlled case study, not a contemporary frontier capability comparison. Pin HF revision. A catalog-verified current efficient API model supplies only an auxiliary prompt control, never a surrogate for training.
**Independent variables.** Edit identity (2+2→5 primary; 2+2→6, 3+3→7, France capital→Rome robustness); optimization seeds 11/22/33; restricted single-layer FT, FT+KL (strengths 1/10), paraphrase FT+KL10, LoRA+KL10. Primary all five methods, secondary exact FT and FT+KL10. Add true-answer sham and routing controls.
**Optimization.** Pilot dev-only learning rate: FT 2e-5, LoRA 1e-3; 40-step maximum, evaluate efficacy and dev drift at steps 0/5/10/20/40. Single middle/late MLP down projection (layer18/28); no claim of prior causal localization. Select earliest checkpoint with >=.95 exact target first-token probability and greedy correct target; otherwise maximal target probability. Replay16 sampled independently per step from 400 train sums and 128 train factual prompts. Four edit examples per step; supervised answer plus end-of-turn; breadth samples exact plus four train paraphrases. Stochasticity is replay/LoRA initialization. Equal update and supervised-token budgets; total input token discrepancy explicitly reported. ROME/MEMIT excluded because subject/covariance assumptions are unvalidated here.
**Data/splits.** Primary all1879 held-out arithmetic rows, 128 CounterFact test prompts, 32 GSM8K test problems (exploratory capability only), 16 WikiText test passages capped64 tokens. CounterFact train supplies preservation prompts. Target train overlap is intentional; all other overlaps must be audited. Secondary edits use a deterministic transformed suite with recomputed local-rule oracle and remove their target from preservation. Selection uses dev only. Exact target, spacing, leading answer tokens and raw/chat formatting are checked first.
**Metrics.** Greedy answer match and exact output agreement; arithmetic normalization only for unambiguous scalar answers. First-token target probability is a confidence diagnostic, not full response probability. Full-vocabulary KL on fixed reference prefixes and WikiText next-token NLL; same-prefix distributions only. Separate paraphrase, dependent, neighboring, distant, other-operation, factual and text strata. Report base-known accuracy denominators and all failures. No assertion of universal preservation or genuine belief.
**Hypotheses/statistics.** H1: preservation reduces collateral drift at adequate efficacy. H2: broader training increases semantic transfer (possibly damage). H3: exact routing achieves literal isolation but little transfer. Primary contrasts KL10 versus FT and breadth versus KL10, paired across3 seeds; report seed range/SD and paired percentage-point effects. Exact sign-flip tests (8 permutations) cannot yield strong significance with3 seeds; report this instead of pseudoreplication. Descriptive family-cluster bootstrap95% intervals within the finite suite; distinguish these from population/model uncertainty. Holm correction for two primary contrasts. No powered universal null test; near-zero leakage is a finite-suite finding.
**Expected outcomes and success criteria.** A useful result maps tradeoffs even when edits fail. Successful execution requires baseline audit, real weight updates, held-out raw outputs, multiple seeds/targets, explicit failed conditions, reproducible scripts/plots/report. Evidence for shallow isolation is high exact efficacy with low held-out transfer; evidence for depth requires dependency use and robustness, not only paraphrases.
**Milestones.** Motivation/planning; setup/data+pilot; implementation+validation; all experiments; analysis; documentation+reproduction. Allow25% debugging buffer. Anticipated one-GPU runtime tens of minutes to a few hours, measured rather than promised. Store configs/logs/checkpoints incrementally. SDF-scale replication and mechanistic intervention are explicitly deferred within existing direction ranking.
